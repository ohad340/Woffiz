# Project instructions
Read PRD.md and ROADMAP.md before planning work.
Before building or changing any UI, read DESIGN_SYSTEM.md and follow its colors, typography, spacing, radius, components, states, responsive and accessibility rules.
Use the proposed tokens consistently. If a change is needed, explain it and update the design document rather than inventing ad-hoc variants.

## Delivery
- Start each phase in Plan mode and present the scoped plan for review before implementation.
- Implement only the current phase. Do not combine phases or expand scope.
- User-facing product copy is Hebrew with RTL; code and engineering docs are English.
- Communicate with the owner in Hebrew, concisely.
- Confirmed requirements outrank proposed defaults. Ask only when a blocking decision cannot be reasonably resolved.
- Preserve existing repository work. Verify dependency APIs against current official docs.
- Keep all secrets server-side and out of source control.
- Clearly label fixtures; never portray demo AI or videos as production integration.
- Do not provision paid resources or publish publicly as part of local scaffolding.

## Non-negotiable product behavior
- One continuous mixed-topic path, not parallel topic tracks.
- Only explicit owner mastery confirmation unlocks the next level.
- Ordinary practice reports, elapsed days and video playback never unlock.
- Previous levels remain reviewable and review never advances the frontier.
- AI content generation cannot update mastery or rewrite completed history.
- No chat, payments, social features or native apps in the MVP.

## Validation
Test ownership, progression transactions, retries, stale AI jobs and media compatibility.
For UI work check Hebrew RTL, keyboard focus, reduced motion and mobile overflow.
Summarize the implemented behavior, relevant checks and remaining blockers.
